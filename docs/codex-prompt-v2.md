### 第一优先：一案真实闭环
恢复服务，核对 SearchPro 官方接口与当前代码。密钥只读后端环境变量 TENCENTCLOUD_WSA_APIKEY，不输出密钥或请求头，不放入 VITE_*、源码、日志、导出或聊天。

先跑一案完整 live 调查并核对原文，再扩三案。记录真实查询、时间、RequestId、结果、原文 URL、定位、短摘句与核对范围。当前旧记录为 0/3，不能自动沿用为现在已完成或已失败的事实；以新运行记录为准。

缺密钥时保持明确错误、零真实成功，不自动转 mock。需要用户操作账户时，只说明具体缺口及本机配置步骤，继续独立可做的代码/测试/材料工作，不反复请求笼统确认。MockTransport 和离线夹具不能计入真实联网证据。

沿用官方 POST https://api.wsa.cloud.tencent.com/SearchPro，Bearer 服务 API KEY、最小 Query 请求，逐项解析 Response.Pages 的 JSON 字符串。相关性 score 不作真实性概率。P0 每案最多 3 次请求尝试，包含重试；P1 可额外最多 1 次由缺口触发的补查；错误不无限循环。三个案例不是三个 HTTP 调用。

### 第二优先：一条说法的条件审计
扩展现有请求与结果区，支持输入一条硬件参数或社区经验。P0 只覆盖现有板卡的 I/O 条件、软件/算法适用条件与生命周期，不假装能通用解析所有网页。

保存原说法、原出处、精确型号、板卡/固件版本、字段与工况。输出：
- supported：精确对象与条件下原文支持；
- contradicted：同一对象和条件下存在明确冲突；
- conditions_differ：型号/传感器/分辨率/流程等不同，不能迁移；
- insufficient：无出处、仅摘要、缺条件或无法核对。

主张四态和候选 pass/fail/unknown 分开。原网页可打开、搜索命中官方域名、参数看似常见均不足以证明主张。社区经验不写回官方规格，转载不算独立复现。商业推广信息与技术证据分开，不能据购买链接判假。

采用有界规则、已核对原文和显式人工复核；可以让用户提供原文摘句及 URL，标明由谁、何时、核对了什么。只有“已点确认”却没有具体证据时不能升级 supported。静态库人工证据与本次 live 新线索保留不同来源/时间，不把固定库伪装本次自动查证。

优先修正电平语义：供电、I/O 输出电平、输入耐压不混用。需要知道谁向谁发送、具体引脚及是否有转换电路。RT1062 官方页标 3.3V 输出/耐受，H7 Plus 页标 3.3V 输出/5V 耐受，不能互用。缺方向/阈值/引脚证据时 unknown；不要仅用一个电压数值的相等与否保证整个链路兼容。

### 第三优先：让个人适配真实影响建议
加入最小 profile：编程/工具基础、Linux 经验、已有器材、剩余可投入小时、可用调试工具；允许“不知道”，标用户自述。

用透明规则输出适配风险、同技术状态内的排序与验证动作。最多问两条确实会改变结果的问题，允许不追问。每个问题展示为何要问、影响哪些候选。先解决技术歧义，再补适配条件。

保持这些不变量：
- 技能、熟悉程度和时间不能改变参数事实、禁用项或电气冲突。
- 用户明确“只能用现有器材”时才把器材范围作为硬限制；单纯“已拥有”是资源信息。
- 已有停产板卡不等于板卡不可用；没有板卡也不能凭库存摘要保证明天到货。
- 缺少预算/功耗/实际 FPS 证据就保留未知。
- 全部候选失败或待核验时如实无可确认方案，不能为了演示强制翻转榜单。
- 不输出成功率、预测几小时完成、新生平均调试轮次等无数据结论。

保存修改前后的会话快照，在现有结果区和导出中显示：改了哪个条件、哪个风险/候选/排序改变、依据哪条规则或证据；没有变化就说明没有变化。优先本次会话实现，不为持久化或独立页面延误。

### 第四优先：把缺口变成可执行动作
每个主要风险给出：所需现有器材、步骤、可观察的通过条件、失败后的下一选择、资料或例程链接。建议“30 分钟”是验证时间预算，不是成功完成承诺；与用户当前基础和器材不符时调整动作。没有复现不写“已验证”。
