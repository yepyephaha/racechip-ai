产品原则（按用户补充更新）：可以借鉴并整合成熟方案的赛题拆解、需求澄清、来源核验、兼容检查和验证清单，不要求每项功能都与竞品不同。以面向电赛新生的完整使用流程和实际可用性为目标。代码与素材复用注明来源并遵守相应许可；竞品已有某能力不构成删去该能力的理由。

## 1. 本轮目标与范围
用一个可演示闭环回答：“这条硬件参数或工程经验，对我现在的赛题和条件是否适用？我接下来该验证什么？”

必须先有一案端到端真实查证，再扩成三份真实查询材料。完整闭环为：
输入赛题及一条待核查说法 → 定位型号/版本/工况 → 元宝搜索 → 核对原文 → 主张结论与证据缺口 → 硬条件筛选 → 队伍适配风险 → 修改条件后的解释 → 最小验证动作。

P0 主张核验限定到现有板卡的少数明确字段：I/O 信号条件、具体软件示例/算法适用条件、产品生命周期。未覆盖的字段保留证据不足。不临时建设通用网页抓取器或通用“AI 判假器”。

## 3. 两种判定必须分开
### 3.1 主张四态
| 状态 | 判定条件 | 例子 |
| --- | --- | --- |
| supported：证据支持 | 精确型号、字段、条件匹配，已核对对应原文 | 原文明确列出该型号的接口 |
| contradicted：证据冲突 | 同一对象与条件下，主张与原文明确矛盾 | 向仅标 3.3V 耐受的 RT1062 I/O 直接输入 5V 的“安全”主张 |
| conditions_differ：条件不同 | 型号、传感器、分辨率、固件或处理流程不同，不能直接迁移 | MT9V034 的帧率经验不能直接证明 OV5640 + AprilTag 达标 |
| insufficient：证据不足 | 无原出处、只见摘要、缺条件或无法核对 | “这块板跑得很稳”没有版本、代码、负载与结果 |

找不到反证不算支持；厂商域名只是来源线索；社区身份、赞数、带购买链接均不决定真假。同一作者自述与其转载不算两份独立实测。原文被核对与硬件复现另列状态。

### 3.2 候选方案三态
保留 pass / fail / unknown：任何已证实硬冲突优先 fail；未解决的关键条件为 unknown；全都覆盖才是“通过已录入条件”。主张 supported 不等于方案整体 pass。技能与时间只参与适配，不能提升技术状态。

必须修正现有单值逻辑电平检查的边界：
- 供电电压、I/O 输出电平、I/O 输入耐压分别处理。
- 单有“对方是 5V”不足以判完整双向兼容；应明确谁向谁发送、具体引脚、是否有电平转换。
- 本轮已读到 OpenMV RT1062 页标 I/O 输出和耐受均为 3.3V；H7 Plus 页则标输出 3.3V、耐受 5V。这是不同型号，不能移用。
- 对未建模的引脚例外、阈值、转换器与时序要求标 unknown，不建立“电平相等=整个链路兼容”的保证。
来源：[RT1062](https://openmv.io/products/openmv-cam-rt)、[H7 Plus](https://openmv.io/products/openmv-cam-h7-plus)。

## 4. 最小数据契约
在现有 AnalyzeRequest 上增加可选字段，旧请求仍可使用。
- claim：原说法、来源 URL（可空但须说明）、来源类型、精确板卡 ID、字段、版本与工况。P0 可用结构化表单，文本规则只辅助提取。
- profile：编程/工具熟悉度（含“不知道”）、Linux 经验、已有器材、剩余可投入小时、可用调试工具。均标“用户自述”。
- constraints：保留原有硬条件；用户明确“只能使用现有器材”时增加器材范围限制，不能当偏好。
- signal_context：仅在电平核验时要求信号方向/具体接收端/是否有转换；信息缺失不得自行补齐。

响应新增：
- claim_checks：主张、四态、理由、匹配条件、差异条件、支持/冲突证据 ID、缺失项。
- evidence：在旧结构上补 exact_model、revision、test_conditions、locator、excerpt、retrieved_at、review_status、review_method。无页码用章节/段落，不能编页码。
- suitability：每个候选的适配规则、触发条件、风险、缺失输入、验证动作。
- change_summary：前后输入变化、受影响候选/风险/排序、变化理由；没有变化就写没有变化。
- verification_actions：前提器材、步骤、可观察通过条件、失败后下一步、官方示例或讨论链接、suggested_timebox_minutes。

manual review 需保留核对人标识/时间、具体摘句与定位及核对范围；勾选按钮本身不能制造证据。摘录与来源缺失时，不应进入 supported。新字段不得把旧静态证据伪装成本次实时核验。

不为比赛引入账号系统或数据库。前后比较可用本次会话快照；优先在现有 analyze 编排中重算。如果重用已有证据，应显示证据时间与重用状态；重新搜索则显示实际新增请求，不能伪装零调用。跨会话历史留待赛后。

## 5. 检索接入与来源边界
沿用后端服务 API KEY：
- POST https://api.wsa.cloud.tencent.com/SearchPro
- Authorization: Bearer（从 TENCENTCLOUD_WSA_APIKEY 读取）
- 最小请求 {"Query":"..."}；Response.Pages 是需逐项解析的 JSON 字符串数组。
- score 是检索相关性，不是真实性概率。密钥不得进入前端、报告、日志或截图。

本轮不换模型供应商、不增加 MCP 客户端。Query 改为围绕**选中的精确型号和待核查字段**，替换现有三个泛查询，而非在其上无限叠加：
1. 精确型号＋字段＋官方文档；
2. 具体版本/算法/传感器＋适用条件；
3. 精确问题＋社区复现/官方示例。

P0 仍至多三次请求尝试；P1 最多加一次缺口补查。失败不循环重试。找不到正文时允许“仅搜索线索”，保持主张证据不足。可让用户粘贴原文摘句和 URL，再明确标注人工核对；不要将其伪装自动抓取或真实硬件复现。

官方文档：[服务 API KEY](https://cloud.tencent.com/document/product/1806/130615)、[SearchPro 参数](https://cloud.tencent.com/document/api/1806/121811)。需要限定网站时遵守 Site 每次一个域名及开通版本限制。不要保证可检索微信全部内容；[官方 FAQ](https://cloud.tencent.com/document/faq/1806/121804)注明目前不支持微信公众号。

## 6. 轻量画像与追问的执行规则
P0 用明确可解释的规则，不做机器学习预测、不输出成功概率或“平均几小时能完成”：
- 无 Linux 经验且剩余时间很短：Linux 方案增加部署验证风险及相关动作，不改变硬件事实。
- 已有某板卡：减少该板的采购等待风险，但是否可用仍要看型号、状态与赛题；停产不等于手中板卡失效。
- 只有 C 基础：新语言/工具链列为待验证负担，不直接判不能做。
- 缺少验证所需工具：标明验收缺口，建议在可用工具范围内完成的检查，不虚称已测。
- 剩余小时未知：不自动填“24 小时”；直接标画像缺口。

最多提出两条会改变当前判定的问题，允许零条。优先问技术歧义，再问队伍适配。可为每条追问写 question、reason、affected_candidates；没有变化依据就不问。任何“很短”等阈值是可见的产品规则/假设，不得写成经过研究证明的门槛。

排序保持硬状态优先。适配因素只在同状态内比较，显示每条贡献或风险，不让新分数覆盖 fail。所有方案都不成立时，明确无可确认方案，不为了展示翻转强推型号。

| 案例 | 问题 | 本轮已找到的原文锚点 | 应体现的边界 |

如果某案的原文/查询失败，按真实情况输出不足，或换成能复核的问题；不编造一个卖家或 UP 主错误。每案保存：完整输入、查询词、请求状态/RequestId、原文链接/摘句/条件、结论、人工核对记录、页面截图或录屏、报告。保存的历史实录注明时间，现场不可冒充新搜索。

## 8. 验收和证据
先运行既有 verify.ps1；旧记录 37 项测试只作基线，不假定当前仍通过。新增有意义的边界测试：
1. live 缺密钥/失败/空结果时不转 mock，不产生本次“已核实”。
2. 只有候选同名或官方域线索，没有匹配字段原文，主张不得 supported。
3. 改型号、传感器、版本或工况后，不继续沿用不匹配的事实证明。
4. 供电不代替 I/O；方向或输入耐压未知时不自动判兼容。
5. 用户技能/剩余时间变化不改变事实真值、禁用项与电气硬冲突。
6. 仅有现有器材限制时，库外/未持有候选不得混入可选组；用户自述持有不等于实测可用。
7. 全部 fail/unknown 的结果真实保留；低证据覆盖不以排序分补偿。
8. 社区经验不能直接覆盖官方规格；版本完整不等于已经独立复现。
9. UI 前后修改能解释变化或明确无变化；MD/JSON 保留模式、来源、人工范围和变更。
10. 所有“建议 30 分钟”都是验证动作时间预算，不是交付耗时预测。

可准备 12 条小样本主张回归（四态各 3 条），合成输入明确标记；真实三案另存。记录误判为“支持”的错误/不足样本数量、支持结论可定位原文的数量、关键约束漏项数量，并给出分子分母。未运行就写未测；不把小样本写成通用准确率，不套原报告 10%/80% 等无依据阈值。

浏览器只需验证现有工作台：输入→真实/错误→主张→改变条件→证据→导出；再检查窄屏、空态、加载和重复提交。没有 UI 修改则不为文档补跑全套浏览器测试。

## 10. 明确后置与对外表述
截止前后置：PDF/OCR、截图识别、价格监控、通知、SQLite/账号协作、全量元器件库、完整 BOM、真机性能预测、长期队伍跟踪、多代理产品架构和通用自动抓取。

可说：有界规则核验、原文可追溯、适用条件比较、队伍适配风险、可解释变更、待验证动作。
仅实际完成后才能说：自主深度调查、三份真实查询、硬件复现。
不说：国内首个/唯一、已证明做得完、成功概率、AI 判断所有经验真假、未测准确率/节省比例。
