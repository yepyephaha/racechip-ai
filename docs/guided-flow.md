# 一句话到完整硬件方案

本轮目标由用户明确指定：大一学生输入“我想做一个循迹小车。”，经过上下文驱动的多轮交互，得到整套方案与商品链接。范围仍面向通用硬件，小车是本轮端到端验收场景。

## 提问与决策方法

参考 [phuryn/pm-skills](https://github.com/phuryn/pm-skills) 的 [访谈](https://github.com/phuryn/pm-skills/blob/main/pm-product-discovery/skills/interview-script/SKILL.md)、[目标与方案树](https://github.com/phuryn/pm-skills/blob/main/pm-product-discovery/skills/opportunity-solution-tree/SKILL.md)、[重要假设优先](https://github.com/phuryn/pm-skills/blob/main/pm-product-discovery/skills/prioritize-assumptions/SKILL.md) 的思路。仅作方法参考，没有安装整套插件，也没有运行其中与当前任务无关的工作流。

- 从用户要实现的效果和实际条件理解任务，避免让新生盲选技术名词。
- 由 TokenHub 每轮读取近期对话、已确认条件、当前工程、上一方案与已有检索证据，决定下一问；没有固定问题顺序。
- 每轮只呈现一个关键问题，允许“不知道，按入门方案推荐”。已回答或明确不懂的参数不能反复逼问。
- 对比路线的适用条件与代价；未知技术细节可转为采购/验证项，避免无休止访谈。
- 建议假设与用户明确条件分别保留；已有器材必须有用户原句支撑。

## 整套交付内容

`BuildPlan` 包含路线、选择理由、规格、数量、用途、配套检查、套装包含物、功能覆盖、装配顺序和验收检查。采购规格是模型建议，不自动变成已核实器件事实。

对于小车，检查移动、支撑、感知、控制、驱动、供电、电池及匹配充电、线材接口、固定与下载工具。底盘套装已含轮子、电机和固定件时列明包含物，避免重复购买。其他硬件由模型按自身依赖拆分，不强套小车清单。

当形成完整方案时，网页自动启动元宝采购检索；最多三个采购项并行，每项先查京东详情，缺少匹配链接时再查全网和淘宝，最多三次查询。每项单独保留真实查询词、RequestId和返回来源，进度落盘。刷新恢复既有任务；后端重启导致中断时明确显示中断。

商品形态可由TokenHub依据实际候选标题与摘要辅助匹配；模型只能选存在的候选ID，不能生成URL，也不能认证SKU或电气兼容。商品卡只链接实际返回的商品详情 URL，不生成虚构 item ID。页面写明匹配与未匹配的关键词；摘要报价、起售价、多 SKU、不同币种和整套到手价分开。没有明确报价时保留未知，不能声称低于预算。没有链接的项保留原始来源和检索词，不伪装为可购买商品。

完整清单可合并到可编辑 BOM；重复合并同一方案不会重复添加。需求变更后，旧采购清单不能套用到新方案。工程导出保留方案、采购 CSV、来源、对话和模型/搜索记录，不在导出时重新调用 API。

## 模拟与真实结果的边界

`scripts/simulate_novice.py --live` 的用户回答是明确标记的隔离模拟输入。追问、方案与商品检索来自实际 TokenHub / 元宝调用，逐轮保存在 `artifacts/novice/session.json`。网页回放逐次显示一轮，回放新增 API 请求为零。

模拟不是用户研究证据，也不表示硬件已经装配、测试、购买或正式参赛提交。具体 SKU、电气与机械配套、到手总价仍需按来源和实物核对。
