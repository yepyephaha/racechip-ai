## 0. 结论先行（如果只读一段）

**1. 国内已经出现"与本项目机制高度一致"的作品，但尚未检索到"场景完全一致"的作品。**

拆开看，你主张的七个能力块，每一块都已有真实先例，其中至少三块比你现在的 P0 做得更深：

| 你的主张 | 已有先例 | 成熟度 |
| --- | --- | --- |
| 多源事实核验 / 三态结论（通过-待核验-排除） | **RoboParts**（开源，2026-08）已在具身零部件上实现"能/不能/不知道"三态 fail-closed 判定，且用代数律＋变异测试守住"不判假绿" | 比你更严谨 |
| AI 选型＋参数溯源＋BOM 风险 | **元器精灵 / 与非AI / CELUS** 已商业化，均在 2025–2026 上线，均有来源引用 | 比你更完整 |
| 主动追问澄清需求 | **专利 CN120011648A**（杭州四维映射，2025-04 申请）已把"异常需求→反馈用户→重新交互"写进权利要求 | 已进专利 |
| 个性化推荐＋能力画像 | **挑战杯 2025「人工智能+」国赛一等奖**已有"多智能体认知诊断＋个性化路径"作品 | 已获国家级奖 |
| 赛题解析 → 器材选型 | **NUEDC Engineering Skill**（2026-07 开源）已做电赛评分合同＋器件级 datasheet 证据核对 | 比你更懂电赛 |

**2. 真正稀缺的不是"AI 帮你选硬件"，而是"证明这个方案你能做完"。** 现有全部竞品（含最像的 RoboParts、CELUS）都停留在**零件/电路层**的可行性与兼容性，没有任何一个把**"新生的编程基础、Linux 经验、剩余时间、调试能力"**纳入选型目标函数并输出**交付失败模式**。这是你目前唯一还没有被占住的空地。

**3. 最大的风险不是同质化，而是"宣称 > 实现"。** 你的 P0 实际是：确定性关键词规则解析（无大模型）＋ 固定 5 款板卡 / 18 条人工核验证据 ＋ 最多 3 条 SearchPro 查询 ＋ 三态判定。而项目介绍里写的是"AI Agent＋自适应提问＋多源事实核验＋个性化推荐＋兼容性分析"。**评委只要点开试用三次，就会发现这中间差着一个数量级。** 侦探赛道评审权重是"可用性 30%、创意 25%、场景价值 25%、展示 20%"——可用性权重最高，正好打在你的短板上。

**4. 侦探赛道的结构性同质化风险很高。** 赛道官方定义就是"用元宝搜索 API 做个查证工具：输入一个问题→找到多方来源→输出结论＋依据＋来源"。**"带来源的查证卡"是这个赛道的默认形态，不是差异化。** 你和几十支队伍会交出同一个形状的东西。差异只能来自：**核验对象的专业性（datasheet vs 新闻）、错误发现的确定性（能当场抓出一个假参数）、以及结论的可执行性（不只是"可信/不可信"，而是"你能不能做完"）。**

### 1.2 证据等级（后文每条都标注）

| 等级 | 含义 |
| --- | --- |
| **A｜已核实可运行** | 有官方站点/仓库/公开文本，功能可直接看到或代码可读 |
| **B｜已核实存在，功能未实测** | 官方页面或第三方目录确认存在，但我未实际跑通全部功能 |

### 1.3 必须声明的调查局限（直接影响结论强度）

1. **微信小程序、小红书站内、B 站视频正文无法完整抓取**。这三处恰恰是学生作品最密集的地方。因此"未检索到"**不能**推出"不存在"。
2. **互联网+/挑战杯获奖名单为分省分散的 PDF 与通稿**，无法穷举近五年数十万件作品。我只能通过"关键词×获奖公示"做定点抽样，抽到的相似作品已列，**不代表没有更相似的**。
3. **商业产品的真实能力无法穿透**（元器精灵、与非AI、CELUS 均需登录/付费），我只核验了公开功能页与官方新闻稿，**未做功能实测**，故标 B。
4. 检索中出现**明显的 AI 生成 SEO 垃圾内容**（例如某云计算厂商站点一篇"智能车竞赛总决赛"文章，声称"72% 的团队采用多线激光雷达与视觉融合""91% 效率创赛事纪录"，无任何数据来源、文风为模型生成）。**此类内容未采信**，也建议你在做事实核验时把它当作反面样本。

### 3.3 最相似的 5 个项目，逐个拆

#### ① RoboParts —— 威胁等级：**最高（机制层面被正面覆盖）**

- **目标用户**：开源机器人构建者、具身智能研究者、RoboCup/人形与四足队伍
- **核心功能**：粘贴 BOM → 两两兼容性矩阵 → 可互换选型组 → 冲突告警；四维判定（机械法兰 ISO 9409-1 / 电气电压 / 通信协议 / ROS 支持）；不兼容时直接给可 3D 打印的转接件；提供 MCP 服务供 Agent 调用
- **技术路线**：**不是 LLM**，是"判定引擎＋三条代数律（可靠性、证据单调性、不可判定边界）＋78 项 CI 闸门＋变异测试（6/6 杀死率 1.00）"。数据采取 `source_tier A/B/C + confidence + last_verified`，`verify_vendor_sources.py` 用真实 HTTP 校验后升 A 级
- **实际完成度**：**A，且工程纪律明显高于 RaceChip P0**。它公开了负结果（10 条被证伪的假说）、验证反模式（12 条）、突变分数落盘
- **商业模式**：代码 MIT、数据 CC BY 4.0，部分字段锁定付费；"我们不卖零件，所以没有理由骗你选一个"
- **优势**：中立性可证明；三态语义有数学约束；可被 Agent 直接调用（MCP）

- **未解决问题**：如何把"不知道"从 90% 降到可用的水平（这是所有做硬约束核验的项目都会撞上的墙）
- **对你的直接冲击**：你的"通过/待核验/排除＋未知不当 0"在**方法论上不新**，而且你的规模（5 款板卡）远小于它。**你不能再用"我们不瞎猜"当卖点**——必须用"我们知道在电赛场景里该问什么、以及答不出来时该让学生去做什么"来接住。

#### ② 元器精灵 PartGenie —— 威胁等级：**高（产品形态最接近你的"成品想象"）**

### ④ 最值得重点打造的 3–5 个创新点

**创新点 1：可反驳的约束账本（Refutable Constraint Ledger）**
不是"提取约束"，而是每条约束都带：原文摘句 + 出处（页码/章节）+ 单位归一 + **歧义标注** + **冲突取严规则** + **"若此条理解错误会导致什么后果"**。
差异化点：**允许用户逐条反驳**——用户点"这条我理解错了"，系统重算并展示哪些结论翻转。这是"可审计"和"可对话"的合体，竞品全是黑箱输出。
可验证：构造含歧义/单位陷阱/隐含约束的赛题集，测"约束抽取召回率"与"用户纠正后的收敛轮次"。

**创新点 2：交付可行性评分（Delivery Feasibility），而非性能评分**
输出不是"推荐 RT1062"，而是：
> "该方案在你的条件下预计需要 3–4 轮调试；最大失败点是摄像头帧率不足导致 PID 抖动；历史上新生队伍在此卡点平均耗时 6–10 小时；若 48 小时内无法跑通，降级路径为 OpenMV 例程改参数。"

需要的输入：编程基础、Linux 经验、已有硬件、每周可投入小时数、交付期限、风险偏好。
差异化点：**竞品优化"设计正确性"，你优化"完成概率"**。这是唯一没人占的位置。
可验证：跟踪 3–5 支真实队伍，比对"预测卡点"与"实际卡点"的命中率。

**创新点 3：经验证据分级（Experience Evidence Grading）**
把"社区经验"从"参考"变成**带等级的证据**：
- E1 可复现（有完整代码/参数/硬件版本/实测数据）
- E2 部分可复现（缺版本或缺参数）
- E3 轶事（"我用过，很稳"）
- E4 疑似推广/软文（含购买链接、无实测）
并强制：**E1–E4 都不得作为硬规格使用**，只能生成"验证动作"。
差异化点：**没有任何竞品对"经验"做分级**。RoboParts 只对厂商声明分级（A/B/C），对社区经验完全不做。
可验证：构造 20 条真实论坛/视频经验（含 5 条已知错误），测分级准确率与"错误经验拦截率"。

**创新点 4（可选）：声明-官方差异检测（Claim vs Official Diff）**
抓电商页/测评文/UP 主口播里的参数声明，与官方 datasheet 逐字段比对，输出"差异表 + 可能的成因（口径不同/型号不同/过时/夸大）"。
注意：RoboParts 有"参数虚标怎么辨别"的**内容专栏**，但**不是自动核验工具**。你做成自动化，仍有空间。
风险：需要抓取与解析能力，P0 阶段做不完，建议作为 P1 的演示片段而非主打。

**创新点 5（低成本高回报）：采购前 30 分钟验证清单**
每个推荐方案自动生成"下单前你能自己验证的 3 件事"：
- 官方页面是否仍在售/是否停产（附链接与访问日期）
- 关键接口在官方文档第几页（附页码）
- 一个能在 30 分钟内跑通的最小实验（附例程仓库）
差异化点：**从"建议"变成"可执行动作"**，且直接呼应侦探赛道"来源可追溯"。

> **取舍建议**：1024 只剩一天，**只做 1＋3＋5**（都能在现有 P0 上加，不需重写架构）；2 作为"创新点陈述 + 小样本实验"呈现，不承诺上线；4 砍掉或只做静态演示。

### ⑤ 如何设计"能证明差异化"的实验

实验设计的原则：**每个实验都必须能证伪你自己的卖点**。以下 6 个按优先级排列。

| 编号 | 实验 | 设计 | 指标 | 若失败说明什么 |
| --- | --- | --- | --- | --- |
| **E1** | 基线对照（必做） | 取 10 道真实赛题（含 2025 电赛 C 题单目视觉、智能车视觉组等），三种方式各出方案：①直接问元宝/DeepSeek 联网 ②元器精灵或与非AI ③RaceChip。**盲评**（隐去来源，请 3 名有电赛经验的学长打分） | 可直接执行率、证据可点开率、冲突识别数、方案被采纳意愿 | 若 RaceChip 不显著优于①，项目不成立 |
| **E2** | 假绿率（最关键） | 构造 30 条声明集：10 条真、10 条已知错误（虚标/过时/型号混淆）、10 条证据不足。看系统把它们判成"通过"的比例 | **False-Green Rate（把假的判成通过）**、Unknown Rate（判成不知道） | 若假绿率 >10%，"多源核验"是空话；若 Unknown Rate >80%，产品不可用（RoboParts 就卡在这） |
| **E3** | 追问增益（消融） | 同一批用户，A 组用固定表单，B 组用主动追问；记录最终方案变更率与用户自评信心 | 方案变更率、追问轮次、信心提升 | 若变更率 <20%，追问是装饰 |
| **E4** | 经验分级有效性 | 20 条真实社区经验（含 5 条错误），人工标注金标准，测系统分级 | 分级准确率、错误经验拦截率 | 若拦截率 <60%，不如直接标注"未核验" |
| **E5** | 交付预测 | 跟踪 3–5 支队伍一个备赛周期，记录实际卡点 | 卡点命中率、时间预估误差 | 命中率 <50% 则退化为"定性提示"，不要宣称"预测" |
| **E6** | 溯源审计 | 随机抽 20 条结论，请第三方按链接逐条复核 | **Evidence Traceability Rate**（可复现比例） | <90% 不要写"证据链" |

**必须在材料里公开的三个数**：False-Green Rate、Evidence Traceability Rate、Constraint Recall。**敢公开这三个数，本身就是最强的差异化**——因为竞品一个都不公开。

### ⑥ 1024 侦探赛道：竞争优势、风险与优化建议

**赛道事实（官方，已核实）**
- 赛道定义：用元宝搜索 API 做查证工具，"输入一个问题 → 找到多方来源 → 输出结论＋依据＋来源"
- 评审权重：**可用性 30%、创意 25%、场景价值 25%、展示 20%**
- 侦探前三须使用元宝搜索；需提交**三份真实提问的录屏或截图**，每份含答案、简短说明、来源链接
- 深度调查、持续监测、截图查证为**选做**，做了须加演示
- 时间：10-25 15:00 封板，16:00 提交截止

**竞争优势（真实存在的，别谦虚）**
1. **核验对象有天然权威层级**。新闻查证只能比"哪家媒体更权威"；硬件查证可以做到"原厂 datasheet > 代理商页 > 电商页 > 论坛帖 > 视频口播"。**层级清晰＝核验可判定**，这是侦探赛道里极少见的"结构化事实"场景。
2. **能当场抓出确定性错误**。"某开发板标称支持 60fps，官方手册写最大 30fps@VGA"——这种打脸是可截图、可复现、可点开原文的，**观赏性远高于"这条传言存疑"**。
3. **结论天然可执行**。查证新闻的终点是"信/不信"；你的终点是"买这个、这样接、今晚先跑这个例程"。**场景价值 25 分有真实抓手。**
4. **P0 的诚实性是可展示资产**。你的 mock/live 分离、`search_configured` 不回显密钥、"未完成清单"写得比大多数队伍都清楚——**这在"可用性"评分里是加分项，前提是你把它讲出来**。

**主要风险（按严重度排序）**

| 风险 | 具体表现 | 严重度 | 处置 |
| --- | --- | --- | --- |
| **R1 侦探硬条件未满足** | 三份真实查询 0/3，SearchPro 未连通。**这是参赛资格级风险，不是优化项** | 致命 | 今天必须打通；打不通就改用元宝搜索 Skill/MCP（官方已开放三种接入方式），别死磕一个端点 |
| **R2 宣称>实现** | 介绍写"AI Agent＋自适应提问＋个性化推荐＋兼容性分析"，实际是规则解析＋5 款板卡 | 致命 | **立刻改文案**：把"已实现"与"路线图"分栏写。评委试用后被发现夸大，可用性分会崩 |
| **R3 形态同质化** | "输入问题→多源→结论+来源"是赛道标配 | 高 | 定位改为"**硬件方案的证据审计员**"，演示必须围绕"抓错"而非"汇总" |
| **R4 规模撑不起"深度调查"** | 5 款板卡/18 条证据，一问就出边界 | 高 | 明确圈定"机器人视觉选型"这一垂直口径，**把窄说成设计选择**，而不是假装全能 |
| **R5 演示时长失控** | 3 分钟要讲清"三态＋证据链＋方案"极易超时 | 中 | 用固定脚本：15 秒抛出错误说法 → 30 秒搜索与原文打脸 → 45 秒出方案 → 30 秒展示未知项与降级路径 |
| **R6 真实搜索不稳定** | 网络/额度导致现场失败 | 中 | 录屏兜底＋现场切 mock 并**显式标注**（你已有这个机制，要用起来） |

**具体优化建议（按投入产出排序）**

1. **把"三态"做成主视觉**（今晚就能做）：界面上三个大数字——通过 N / 待核验 N / 排除 N，点进去每条都有原文链接与访问日期。**这是评委 10 秒内能理解的差异化**。
2. **准备"打脸三案"**（替代泛泛的三份查询）：
   - 案 1：某型号标称帧率 vs 官方手册实测条件不符
   - 案 2：某开发板"支持某接口"但电平不匹配（3.3V vs 5V）
   - 案 3：某方案"已被大量使用"但核心器件已停产/欠货
   每案都必须有：错误说法的出处 + 官方原文 + 差异结论 + 对选型的影响。**这三案本身就是作品**。
3. **删掉 P1，保住真实调用**（工程决策）：PDF/OCR、多轮检索、SQLite 历史、价格监测全部砍掉。**你没有时间，而 R1 是致命的**。
4. **加一栏"我不知道"**：把 P0 里"未验证/未完成"清单直接搬进产品页，做成"本报告的证据缺口"。RoboParts 靠"公开登记答不出来的部分"建立了信任，你可以直接借用这个手法（并注明借鉴）。
5. **一句话定位**：不要写"AI 帮你选硬件"。写——
   > **"在买之前，先证明这个方案你能做完。"**
   这句话同时覆盖"侦探"（证明）、"场景价值"（买之前＝省钱）、"可用性"（做完）。
6. **对外分享文案**（官方要求带四个话题）里，**只讲一个数字**：你抓出了几个错误声明、每个都能点开原文。不要罗列功能。
