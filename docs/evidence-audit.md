# 开放主题的证据核验

入口为侧栏“证据核验”。直接输入一句需要查证的话，例如“ESP32只能用3.3V”；精确型号、原话出处和使用场景可以补充，不要求填写赛题或先从固定器件库选择。

## 方法

1. 当前连接的上下文模型识别主题、可核查子问题与歧义，生成贴合本题的查询计划。标准12条，深入18条；厂商资料、用户经验、相反证据、型号与使用条件四种角度均覆盖。
2. 每条查询通过元宝SearchPro实际执行，保存查询词、返回数量、错误和RequestId。来源按URL去重，保留它被哪些查询命中的记录。遇到鉴权或额度错误停止后续查询。
3. 优先读取相关厂商与社区来源，并限制单一站点占用。标准最多读取12份，深入最多18份。读取网页或PDF，保留相关片段和PDF页码；无法访问、超限、需登录或无法提取时明确标记。
4. 模型据实际材料逐条形成“证据支持 / 证据反驳 / 需区分条件 / 证据不足”，并分别列用户经验、相反意见、缺口与下一步核对建议。
5. 程序校对引用的来源ID与连续原文片段。伪造、错配或只有搜索摘要的引用不能作为原文核实。缺少必要厂商原文的确定性硬件规格判断降为证据不足；用户经验只能引用已读取的社区来源。

报告、JSON及查询记录可导出。任务保存在本机，切换工作区或刷新后可恢复显示；后端重启时未完成任务标为中断。停止按钮会停止后续阶段，已发出的上游请求不保证撤销。

## 边界

- 模型输出是基于资料的核查意见，并非硬件实验或对来源真实性的绝对证明。
- “官方资料”类别由研究计划中的厂商域名匹配，仍需看具体文档是否对应精确对象和版本；不是只凭域名判参数成立。
- 一个站点、多个帖子或转载不能自动视为多个独立验证。用户个案不直接上升为所有设备的规格或故障率，不提供虚假的口碑评分。
- 原文读取最多6MB，PDF最多80页、提取文本最多20万字符；模型使用相关片段。不会声称整份长文档已被完整审查。
- 外部来源仅来自本轮搜索结果，公开地址经解析后固定IP连接，检查每次跳转；不向来源站点传递模型或搜索认证头，不读取内网/本机地址。
- 标准检索上限12次、深入18次；模型规划或结构修复也会产生调用。实际次数在报告显示，失败不静默换成模拟记录。

历史 `/api/analyze` 为旧的视觉选型接口，保留旧验收兼容；当前侧栏证据核验已使用独立的 `/api/hardware/fact-checks` 工作流。

## 2026-10-25 实际验收

通过页面提交用户原话“ESP32只能用3.3V”，真实执行12条SearchPro查询，取得109个去重链接；这些都是检索线索，不宣称109个独立或相关结论。最终核对8份有正文的资料：3份乐鑫官方文档、5份社区/经验资料，生成5项子判断与4项带来源和局限的社区经验摘录。涉及其他芯片的论坛内容明确注明不适用于直接证明ESP32规格。

原文读取首次受到本机TUN代理的保留地址解析影响；读取器现通过固定公共DNS解析器的验证TLS取得公网地址，并固定该IP连接，继续拦截本机、内网和保留地址。重读复用原12次搜索结果，没有新增SearchPro调用。2个只有标题的页面未计入正文核对，未影响任何现有引用。HTTP403/521来源保留为未读线索。

真实报告区分芯片、模组、开发板输入与推荐供电范围，并保留绝对最大额定值、具体开发板输入上限及GPIO耐压的原文缺口。未把它们包装成已经确认或本项目实测。

本次两次核验尝试的模型已返回记录合计5次：首次计划校验失败2次；后续成功计划、原文未读时的旧报告、修复网络后的报告各1次。新代码在没有任何可读原文时停止模型结论生成，仅显示线索和缺口。以上次数只描述保存的本轮记录，不代表账号总账单。

118项离线测试与前端构建通过；界面机械检查无发现。实际浏览器验证了直接输入、12条查询的进度恢复、原文重读、最终引用与用户经验显示，源码包包含可查看的验收报告与JSON。没有声称已读取109份原文或独立复现用户实验。
