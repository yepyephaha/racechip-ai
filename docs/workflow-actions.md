# 方案生成与器件搜索的实际操作

## 方案与BOM

项目名、方向和预算是方案输入，修改字段会保存在当前本机项目，但不会在每次打字时自动调用模型或搜索。页面现在明确提供目标输入和“生成方案并搜索配件”按钮。

点击后先用元宝搜索当前目标的参考路线与配套资料，再由模型生成具体采购规格和功能关系草案；普通未知项列为建议假设，必须确认的核心条件在当前页提问。完整草案形成后自动逐项搜索商品，展示实际进度、链接、缺口和请求次数。

检查清单后点击顶部“采用清单，填入BOM”。这一步会新增建议规格与功能关系，更新下方架构和可编辑BOM，保留原有手工项与报价；不会把功能关系草案说成已验证的接线图。相同一轮清单重复采用新增0行。输入或BOM变化时，旧结果标为过期，先更新再采用。

生成任务按当前项目保存，切换工作区、刷新页面可恢复进度；后端重启中断时可以恢复未完成搜索。模型失败后可复用已取得的路线资料重试，避免重复执行相同资料查询。

模型请求对复杂方案使用腾讯云JSON输出模式，并把完整清单字段设为必填，再按本地Schema校验单一采购规格、有效功能关系和输入一致性。修复时把具体字段错误反馈给模型，而不是只让它盲目重写。相关协议见[腾讯云响应格式参数](https://cloud.tencent.com/document/product/1823/135872)。

## 器件与报价

器件搜索现在在搜索框下直接显示加载、错误、匹配型号和实际联网来源。本机参考库另列一段，本机0匹配不会隐藏外部搜索。

输入ESP32S31时可以检索ESP32-S31等分隔符写法；字母和数字必须保持，不把S31自动改成S3。只有来源标题或摘要含完整匹配文字时才给出型号入口，标记为规格、形态与SKU待核验，可以直接加入BOM；其他相关网页仍可打开并辅助人工录入。

器件发现与商家报价分开保存。点击查价格会定位报价区域并执行查询；缺价、多SKU或形态不明不会编成已确认单价。

原问题的原因：联网结果被放在报价区域的折叠来源中，器件发现下方只展示固定本机库；而方案页此前只有字段编辑与手工BOM，没有生成主操作。
