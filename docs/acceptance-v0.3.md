# 2026-10-25 通用硬件与新生完整流程验收

当前范围以 PRODUCT.md 和 guided-flow.md 为准，保留 v0.2 三案证据核验。原生 EDA / PCB、实物装配与公网提交不属于本轮已完成项。

## 实际结果

- 96 项 pytest 通过。新增覆盖模型结构修正、完整方案、已有器材原句、语义匹配不能发明 URL、SKU不得自动认证、Windows 进度读写并发、断点恢复、旧决策拒绝套用、BOM 合并去重与 CSV 默认字段。
- TypeScript/Vite 构建成功。主包约251KB、gzip约81.7KB；回复动效按需加载。Starlette/httpx 有一条既有弃用提示，不影响结果。
- TokenHub 专用 Key 实际调用成功，生产对话每轮由 API 依据上下文决策。元宝 SearchPro 统一承担商品与资料检索。失败不静默回退固定问题树。
- 新生示例从“我想做一个循迹小车。”开始，保存5轮成功交互。用户回答为明确标记的模拟输入；包含一轮针对笼统规格的模拟修正，不是用户调研。第一轮地面/路线、随后焊接偏好和预算，按上下文逐次出现。
- 最终9类必需配件都定位到实际商品详情：UNO、4路TCRT5000、L298N、二驱底盘/电机/65mm轮/万向轮套装、AA带开关电池盒、AA碱性电池本体、5V移动电源、杜邦线与装配工具。工具的不同部件标记“一并购买”；替代商家标记“备选”。
- 商品语义匹配仅可选取元宝实际返回的候选 ID，URL由服务端映射；模型不能生成商品地址。名称形态匹配不等于SKU、电气、供货或价格认证。
- 实际浏览器导入、资料引用问答、保存、恢复、整套BOM与下载走通。将完整清单加入9行BOM，再次加入新增0行；器件 facts 保持空/待核验。恢复已有方案没有新增采购任务。
- 浏览器下载的 complete-hardware-handoff.zip 含9行BOM、9行采购CSV、完整方案、模型对话/查询来源；same_decision=true，ZIP校验通过，导出不重发模型或搜索。
- 桌面1440px和手机390px的最终采购清单均显示9类配件、16个商品链接，无整页水平溢出；平板768px入口也已查看。初始页三尺寸测量与源码检查均0 FAIL / 0 WARN，最终浏览器pageerror为0。已查看逐轮首问、完整清单、配置入口、BOM和引用问答；键盘/触摸控件保留可见焦点与足够点击范围。

## 限制

200元只是模拟用户的预算目标，没有把未知报价当成已经满足预算。AA碱性电池不充电；移动电源充电线、输出与各模块精确接口仍按商品版本核对。整车未进行接线、堵转电流、循迹、续航或性能实测。

商品页可能有多SKU、地区限制、失效或供货变化，必须在购买时确认。海外商家不保证可在中国大陆直接下单或符合预算。没有自动购买、付款、加购或以用户身份发布/提交。密钥只保存在后端进程环境，源码/导出不包含真实密钥。

实际点击底盘第一商家链接后出现Cloudflare校验页，未尝试绕过；该链接不代表已确认可直接下单，另保留其他真实商品来源。已保存的29条元宝请求记录不代表账户总调用量或计费次数；早期中断任务可能存在未落盘的请求。

样例回放只读取已有记录，明确显示模拟用户和历史时间，新增模型/搜索请求为0。源码包中保留历史 v0.1/v0.2 资料，其测试数量和范围不作为本版本当前结论。
